- **Discovery** được phép nhìn, vẽ, đổi cách phân tích. Kết luận tối đa: "có candidate pattern trong mô hình và $D$ này".

### 6.3. Kiểm validity *trước khi đọc*

**Lý do.** Một bảng chưa qua validity mà đã được đọc thì kết quả đã lộ. Nếu sau đó bạn tìm ra bug, bạn đã có ý kiến về các con số sai.

**Đề xuất "mở file hai bước".** `run.py` ghi `cells.csv` đầy đủ, nhưng **in ra trước** một file `validity.csv` chỉ gồm các cột kiểm, chưa có contrast:

| Cột trong `validity.csv` | Đạt khi |
|---|---|
| Bất biến loại 2 và 3 (L3.2 Part 4): $L_{11}\le L_{sm}$; $G_{M\mid S_1}\le\mathbb E\lvert e_M\rvert$; $\delta_A\ge0\ge\delta_B$; $W^{M_0}\le W^{M_1}$ | Mọi ô |
| Ô kiểm âm: sáu contrast `== 0` (N01–N04, P01); $G_{S\mid M_1}$ `== 0` ở ô WD | Mọi ô kiểm |
| $e_{\text{num}}/C_{\text{ref}}$ | ≤ 0,0025 |
| Khối lượng chưa chứng nhận | ≤ 0,01 (ô vượt: HOLD, ghi lại) |
| Cờ cặp (2·dt cuối, dt cuối): max$\lvert\Delta G\rvert/C_{\text{ref}}$ | Ghi cờ nếu > 0,0025; **không xóa ô** |

Chỉ khi `validity.csv` đạt thì mới mở `cells.csv`. Nếu không đạt, quay lại L3.2 hoặc L3.4, và **chưa** đọc kết quả.

**Vì sao không xóa ô bị cờ.** Xóa ô sau khi thấy nó là "bỏ ô xấu", một forking path. Luật chấm của card (L3.3 Part 1) đã nói trước: ô vượt dung sai làm mịn thì **chưa phân giải**.

### 6.4. Chấm card **trước**, khám phá **sau**

**Thứ tự:** validity → chấm card → khám phá.

- *Vì sao:* nếu khám phá trước, bạn sẽ có ý kiến về pattern. Khi đó, mỗi ô sát ngưỡng là một cám dỗ để "hiểu lại" card.
- *Cách làm:* chạy `score_card.py`, lưu `card_scores.csv`, **commit** nó, rồi mới mở các cột contrast để khám phá.
- *Kiểm:* một người thứ hai, hoặc một phiên AI mới, áp lại luật **bằng tay** trên hai ô và phải ra cùng trạng thái.

### 6.5. `score_card.py`: chấm mà không còn quyền diễn giải

> **Plan hiện ghi:** `score_card.py` "đọc luật từ card, kiểm hash".
> **Tôi đề xuất bổ sung cho card ở L3.3 Part 3:** thêm một khối luật **máy đọc được** *bên trong* card, ví dụ một khối ` ```json card-rules `. Khi đó script đọc đúng khối đó.
> **Vì sao:** luật viết bằng văn xuôi luôn còn chỗ để hiểu theo hai cách. Ví dụ: "≤" là biên đóng hay mở? Ô Q5 gộp theo "mọi ô" hay "ít nhất một ô"? Nếu luật nằm trong card và hash của card được kiểm, thì cả **nội dung lẫn cách hiểu** đều bị khóa.
> **Nếu card đã commit mà chưa có khối này:** chép luật sang JSON, nhờ người thứ hai kiểm bản chép, và **commit bản chép trước khi chạy A04**. Ghi rõ đây là bản chép sau commit card.

**Code.** Mình đã chạy và test trên dữ liệu giả.

```python
"""Chấm prediction card theo đúng luật đã khóa (L3.3). Không có tham số nào để "chọn".

Scientific purpose: phần [PREREG-CARD] của A04. Used by: A04 (ô chính), A05-T (mức luật).
"""
import hashlib, json, re

STAND, FAIL, UNRES = 'đứng', 'không đứng', 'chưa phân giải'

def load_card(path, registered_sha256):
    raw = open(path, 'rb').read()
    if hashlib.sha256(raw).hexdigest() != registered_sha256:
        raise SystemExit('Card khác hash trong exposure register: DỪNG, không chấm.')
    block = re.search(r'```json card-rules\n(.*?)\n```', raw.decode(), re.S)
    return json.loads(block.group(1))                     # luật máy đọc được, nằm TRONG card

def interval(row, q, normalize):
    v, e = row[q], row['e_' + q]
    if not normalize:
        return v - e, v + e
    C, eC = row['Cref'], row['e_Cref']
    if C - eC <= 0:
        return None                                       # D23: loại nhãn tương đối
    lo = (v - e) / (C + eC) if v - e >= 0 else (v - e) / (C - eC)
    hi = (v + e) / (C - eC) if v + e >= 0 else (v + e) / (C + eC)
    return lo, hi

def cell_state(row, p):
    if row['hold']:      return UNRES, 'khối lượng chưa chứng nhận > 0,01'
    if row['pair_flag']: return UNRES, 'chưa hội tụ (2·dt, dt)'
    iv = interval(row, p['quantity'], p.get('normalize', True))
    if iv is None:       return UNRES, 'Cref ≤ e_Cref (D23)'
    lo, hi, t = *iv, p['threshold']
    ok, bad = {'<=': (hi <= t, lo > t), '>=': (lo >= t, hi < t),
               '>':  (lo > t, hi <= t), '<':  (hi < t, lo >= t)}[p['relation']]
    return (STAND if ok else FAIL if bad else UNRES), f'[{lo:.5f}; {hi:.5f}]'

def combine(states, how):                                  # logic ba giá trị (Kleene)
    if how in ('all', 'and'):
        return FAIL if FAIL in states else STAND if all(s == STAND for s in states) else UNRES
    return STAND if STAND in states else FAIL if all(s == FAIL for s in states) else UNRES

def score(rules, rows):
    out = {}
    for p in rules['predictions']:
        if 'parts' in p:
            out[p['id']] = (combine([out[k][0] for k in p['parts']], p['combine']), {})
            continue
        per = {c: cell_state(rows[c], p) for c in p['cells']}
        out[p['id']] = (combine([s for s, _ in per.values()], p['aggregate']), per)
    return out
```

**Từng khối tồn tại để làm gì:**
- **`load_card`** hiện thực bằng chứng nội dung của L3.3 Part 3. Hash khác thì **dừng**, không có ngoại lệ.
- **`interval`** hiện thực khoảng của tỉ số (L3.3 Part 1, đề xuất 2). Khi $C_{\text{ref}}$ không dương sau khi trừ sai số, ô bị loại theo D23.
- **`cell_state`** xét theo thứ tự: HOLD, rồi chưa hội tụ, rồi khoảng so với ngưỡng. Biên đóng và mở được viết riêng cho từng quan hệ.
- **`combine`** hiện thực logic Kleene: "mọi ô" và AND dùng một luật; "ít nhất một ô" dùng luật đối xứng.
- **`score`** chấm từng vế trước, rồi mới ghép (L3.3 Part 1, đề xuất 1).

**Test trên DỮ LIỆU GIẢ** ($C_{\text{ref}}$ = 100, số giả định, không phải kết quả):

| Vế | Ô giả | Đầu vào | Trạng thái |
|---|---|---|---|
| K5 (≤ 0,005, "mọi ô") | A | $G$ = 0,45 ± 0,03 | đứng [0,00420; 0,00480] |
| | B | 0,49 ± 0,03 | **chưa phân giải** [0,00460; 0,00520] |
| | C | 0,10 ± 0,01, $e_C$ = 0,25 | đứng |
| | **gộp** | | **chưa phân giải** |
| Q5 (≥ 0,01, "ít nhất một") | D | 0,80 ± 0,02 | không đứng |
| | E | 1,50, HOLD | chưa phân giải (HOLD) |
| | **gộp** | | **chưa phân giải** |
| P5 = K5 AND Q5 | | | **chưa phân giải** |

Các kiểm phụ cũng đạt:
- đổi B thành 0,60, thì K5 thành **không đứng** (một ô sai làm "mọi ô" sai);
- bỏ HOLD ở E, thì Q5 thành **đứng**;
- gắn cờ chưa hội tụ cho A, thì A thành chưa phân giải.

Bài học từ bảng: **một ô HOLD hay một ô sát ngưỡng có thể làm cả claim "chưa phân giải"**. Đây không phải điểm yếu của luật. Đó là đúng mức hiểu biết mà dữ liệu cho phép.
